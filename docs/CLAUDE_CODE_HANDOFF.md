# Передача проекта TRACE в Claude Code

Состояние на 27 сентября 2026 года. Этот документ описывает проверенную структуру текущего рабочего каталога и порядок продолжения работы. Короткие постоянные инструкции находятся в [`../CLAUDE.md`](../CLAUDE.md).

## Быстрый старт

В PowerShell из родительского каталога `reverse-cheating`:

```powershell
cd .\tracecheck
git status -sb
claude
```

Запускайте Claude Code из корня `tracecheck`, чтобы он получил корневой `CLAUDE.md`. CLI `claude` обнаружен в этом окружении. Для нового компьютера клонируйте `https://github.com/TraceOwner/tracecheck.git`, перейдите в каталог репозитория и запустите `claude`; если CLI не установлен, используйте [официальную инструкцию](https://code.claude.com/docs/en/setup). Для самостоятельной разработки достаточно Node.js и Git; npm-зависимостей у проекта нет.

Полезное первое задание Claude Code: «Прочитай CLAUDE.md и docs/CLAUDE_CODE_HANDOFF.md, покажи `git status -sb`, объясни, какая ветка и какой remote публикуют сайт, затем работай над моей следующей задачей».

## Что это за сайт

TRACE — русскоязычный статический сайт с локальными сценариями проверки Minecraft, GTA V/RP и Counter-Strike 2. Он объясняет признаки, показывает PowerShell/CMD команды и ручные шаги. Запуск происходит на компьютере посетителя по его решению. Сайт не получает результаты команд, не сканирует устройство браузером и не выносит автоматический вердикт. Одна находка — повод для контекстной проверки, а не доказательство нарушения.

Страницы: `/` или `/index.html` — обзор; `/check.html?game=minecraft`, `?game=gta`, `?game=cs2` — проверка; `/methodology.html` — методика; `/projects.html` — игры и серверы; `/tools.html` — инструменты; `/legal.html?doc=offer|privacy|consent|rules|cookies` — проекты документов. Ссылки на игры и инструменты не означают партнёрства.

## Где менять код

- `src/site.mjs` собирает шесть HTML-страниц и копирует ресурсы. Главная разметка — `src/home-page.mjs`, проверка — `src/check-page.mjs`, инструменты — `src/tools-page.mjs`; прочие страницы частично находятся прямо в `src/site.mjs`.
- `src/check.js` содержит сценарии для игр, выбор терминала/игры и копирование. `src/trace-pro-minecraft.ps1` — исходник расширенного Minecraft PowerShell сценария. Сборка превращает его в `dist/minecraft-command.js` и копирует в `dist/scripts/trace-pro-minecraft.ps1`.
- `src/spring.js` — пружинный движок (параметры как в SwiftUI: длительность + bounce, сохранение скорости при прерывании). `src/site.js` — общие взаимодействия: стеклянная липкая шапка, линза навигации, диалоги с zoom от кнопки-источника, «остров» уведомлений у низа окна, появления при прокрутке, FAQ, scrollspy инструментов. `src/motion.js` — оркестрация дыма (наблюдатели, размеры, указатель), `src/smoke-core.js` — шейдер и цикл кадров (ровный ритм по частоте монитора, сначала снижается разрешение, потом частота), `src/smoke-worker.js` — запускает то же ядро в Worker на OffscreenCanvas; без Worker ядро работает в основном потоке. Все стили — единый `src/trace.css` (токены материалов и пружин, страницы, адаптив, reduced-motion). Кривые `--spring-*` генерирует `scripts/springs.mjs`.
- `src/brand.mjs` — векторный знак; `src/tool-icons.mjs` — иконки способов проверки. Шрифты и лицензии находятся в `dist/fonts/`, исходное hero-изображение — `src/hero-trace.png`.
- `dist/legal.js` — черновые юридические тексты. Также `dist/scripts/trace-check.ps1` и `dist/scripts/trace-check.cmd` живут непосредственно в `dist/`.
- `scripts/verify-commands.mjs` проверяет, что команды PowerShell/CMD разбираются и что Minecraft-сценарий находит синтетический пример. Запускается на Windows с PowerShell.

**Сборка не полностью воспроизводит `dist/` с нуля.** `src/site.mjs` обновляет HTML и перечисленные в нём ресурсы, но оставляет существующие `dist/legal.js`, `dist/fonts/` и два `dist/scripts/trace-check.*`. Не удаляйте `dist/` для «чистой сборки». Если переносите эти файлы в `src/`, сначала измените сборщик и проверьте итоговый `dist/`.

## Локальный цикл

```powershell
npm run build
npm run check
npm run dev
```

Предпросмотр: `http://127.0.0.1:4173`. После изменений команд дополнительно выполните `node scripts/verify-commands.mjs`. Проверьте нужные страницы в браузере, клавиатуру и прокрутку, затем `git diff --check` и `git diff --stat`. Для анимаций проверяйте также `prefers-reduced-motion` и слабое устройство/неактивную вкладку. Отсутствие ошибок синтаксиса не заменяет визуальную проверку.

## Публичный Git и деплой

- Публичный репозиторий: [TraceOwner/tracecheck](https://github.com/TraceOwner/tracecheck).
- Продакшен: [trust-trace.lat](https://trust-trace.lat/).
- [`../.github/workflows/pages.yml`](../.github/workflows/pages.yml) запускается при push в `main`, использует Node 22, делает `npm run build` и `npm run check`, затем публикует `dist/` в GitHub Pages. HTTPS для домена был включён. Публикация может занять несколько минут; статус смотреть в GitHub Actions.
- В **этом** каталоге безопасная рабочая ветка — `public-pages`, связанная с remote `github/main`. Старый локальный `main` и remote `origin` относятся к прежнему Sites-хостингу. История старой ветки не предназначена для публичного GitHub. Не выполняйте `git merge main` в `public-pages`, не `git push origin` для продакшена и не отправляйте старую историю в GitHub.
- В свежем клоне с GitHub будет обычная ветка `main` и remote `origin`; это **другой** `origin`, уже GitHub. Всегда сначала смотрите `git remote -v` и `git status -sb`.

Обычная публикация из текущего каталога после проверки изменений:

```powershell
git fetch github
git status -sb
git diff --check
npm run build
npm run check
git add -p
git diff --cached --stat
git diff --cached
git commit -m 'Describe the change'
git push github HEAD:main
```

`git add -p` добавляет изменения по частям; новые файлы добавляйте отдельной командой `git add -- путь-к-файлу`. Проверяйте staged diff на личные данные. Если `github/main` обновился с другого компьютера, сначала аккуратно согласуйте изменения. Для отката опубликованного коммита используйте `git revert`, затем новый push; избегайте force-push.

## Домен и доступность

Домен `trust-trace.lat` обслуживается Cloudflare DNS, сайт — GitHub Pages. Для корня были настроены четыре A-записи `@`: `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`, режим **DNS only**. Для `www` — CNAME на `traceowner.github.io`, также **DNS only**. Пользовательский домен был задан в настройках GitHub Pages; отдельного файла `dist/CNAME` в текущем репозитории нет. Не направляйте эти записи обратно на `chatgpt.site`: прежний хост показывал посетителю блокировку из некоторых сетей. `.openai/hosting.json` относится к старой схеме и не является текущим механизмом публикации.

Последняя техническая проверка: публичные DNS-резолверы вернули четыре адреса GitHub Pages, а последний запуск Pages workflow завершился успешно. Доступ через конкретного провайдера владельца без VPN после переключения не был отдельно подтверждён; не обещайте «доступ из любой точки мира» без проверки реальными сетями. Если домен недоступен, сначала проверьте делегирование NS, ответы DNS, статусы Pages и HTTPS, затем HTTP-ответ из проблемной сети. TXT-записи `_cf-custom-hostname` и `_openai-site-verification` остались от старой схемы; они не нужны для GitHub Pages, но их удаление не требуется для обычной разработки.

## Дизайн и незавершённые вопросы

Владелец хочет оригинальный, детально проработанный desktop-интерфейс: современный строгий гротеск, объёмный почти чёрный дым с редкими яркими вспышками, разные фоны страниц, красивые живые иконки и плавные стеклянные переходы. Особенно важны раскрытие списка игры в стиле «вытекания» и уведомление о копировании, которое должно оставаться на месте при прокрутке. Не считайте текущую реализацию окончательно принятой: последняя явная обратная связь по анимации была критической. При доработке смотрите конкретное состояние сайта до изменений, затем проверяйте его в браузере.

На главной и страницах уже есть WebGL-дым (в Worker, с запасным вариантом в основном потоке), CSS fallback и режим уменьшения движения. Сохраняйте управление с клавиатуры, фокус, Escape, `prefers-reduced-motion` и паузу при скрытой вкладке. Не превращайте движение в задержку доступа к содержимому. Пользователь просил качественный desktop-опыт; мобильная версия не была главным критерием обсуждения.

## Команды, юридические тексты и данные

Названия чит-клиентов и правила игровых серверов меняются: перед обновлением поиска проверяйте актуальные первичные источники и смысл совпадений. Не выдавайте найденное имя процесса, файл или хеш без известного эталона за доказательство читерства. Никаких скрытых запусков, загрузок отчётов или отправки личных данных без нового явного требования владельца и соответствующего пересмотра документации.

Юридические тексты в `dist/legal.js` помечены как черновики: реквизиты предпринимателя и схема обработки данных ещё требуют подтверждения владельца. После ухода от прежнего хостинга проверьте упоминания инфраструктуры в политике cookie. Не публикуйте вымышленные реквизиты или утверждения о готовности документов. Не добавляйте в репозиторий токены GitHub/Cloudflare, содержимое `.env`, локальные настройки Claude и личные файлы.

## Короткий контроль перед передачей результата

1. `git status -sb` показывает ожидаемую ветку и только ожидаемые изменения.
2. Исходники и нужные файлы `dist/` изменены вместе; сборка и проверки прошли.
3. В браузере проверен затронутый сценарий, включая клавиатуру и уменьшение движения для анимаций.
4. Перед публичным push просмотрен staged diff, нет секретов и нежелательной старой истории.
5. После push GitHub Actions успешен; при изменении DNS/домена дополнительно проверены DNS и доступ из нужной сети.
